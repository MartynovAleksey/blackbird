## Context

Раскладка desktop- и web-приложения задаётся настройкой `appearance.tabLayout` (`packages/app/src/settings/model.tsx`). Сейчас у неё три значения: `horizontal` (вкладки сверху), `vertical` (сбоку) и `inbox`. Для `vertical` есть группировка боковой панели `general.sidebarOrganize` (`projects | list | customize | recent`).

У сессии два региона инструментов: правый `side` и нижний `bottom` (`session/session-layout.ts`). Их вкладки дают встроенные GUI-плагины из `packages/gui-plugins`:
- `terminal` — терминал;
- `review` — изменения;
- `browser` — встроенный браузер, только desktop;
- `file` — файлы;
- `context`, `details`, `goal` и другие.

Диалог настроек открывается через `useSettingsDialog()`. Сейчас до него добираются через «Главная → Настройки».

Эталон — desktop-приложение Claude Code (вкладка Code). Пользователь хочет раскладку, которая максимально повторяет его набор возможностей и расположение элементов. То, чего нет в blackbird, записывается в Todo.

## Goals / Non-Goals

**Goals:**
- Четвёртое значение раскладки `native`. Оно собрано из того, что уже есть: боковой панели, группировки по проектам, регионов `side` и `bottom`, вкладок плагинов, диалога настроек.
- Правая полоса иконок и меню «Вид» поверх существующих регионов сессии.
- Эталонная таблица Claude Code → blackbird и таблица Todo для всего, чего нет.

**Non-Goals:**
- Новая серверная или агентная функциональность: всё из таблицы Todo делается отдельными изменениями.
- Изменение раскладок `horizontal`, `vertical` и `inbox`, а также раскладки по умолчанию.
- Пиксельная копия визуального стиля Claude Code. Цвета, шрифты и иконки остаются темой blackbird; повторяются состав и расположение элементов.
- TUI: раскладка касается только desktop и web.

## Decisions

1. **`native` — значение `tabLayout`, а не отдельная настройка.**
   - Причина: раскладка взаимоисключающая с тремя существующими, а переключатель в Настройках уже есть. Отдельный флаг «native поверх vertical» дал бы бессмысленные сочетания.
   - Схема `Schema.Literals` расширяется значением `"native"`. Старые сохранённые значения валидны как есть; `withFallback` уже возвращает значение по умолчанию для неизвестных.
   - Отвергнуто: флаг `experimental.native_layout`. Раскладку выбирает пользователь, а значение по умолчанию не меняется, поэтому флаг ничего не защищает.

2. **Левая панель — та же боковая панель, что у `vertical`, с принудительной группировкой `projects`.**
   - Проверки `tabLayout() === "vertical"` в `shell.tsx`, `titlebar.tsx` и `sidebar-toggle.tsx` заменяются на одну функцию «боковая раскладка»: `vertical` или `native`.
   - Для `native` группировка всегда `projects`; настройка `sidebarOrganize` самого пользователя не перезаписывается и вернётся при переключении на `vertical`.
   - Отвергнуто: отдельный компонент списка сессий. Он дублировал бы виртуализацию, перетаскивание и статусы, которые уже есть.

3. **Кнопка «Настройки» внизу левой панели** вызывает `useSettingsDialog()`. Она стоит в существующем подвале боковой панели (`vertical-tabs-footer` в `titlebar.tsx`), рядом с такой же кнопкой мобильного меню: десяток строк не стоят отдельного файла.

4. **Правая полоса (session rail) — компонент `session/native-rail.tsx`.** По скриншоту Claude Code от 16.11.2026 это горизонтальный ряд иконок в правом верхнем углу над правой панелью: Сессия, Терминал, Изменения, Браузер, Файлы, «…».
   - Иконки — это пункты меню «+» правой панели (`MenuItem` с `menu: "session.panel"`): их уже регистрируют `review`, `browser`, `terminal` и `file`, с иконками и порядком. Плагин сам решает, когда пункт есть, поэтому браузер появляется только в desktop.
   - Клик запускает пункт плагина; для терминала вместо «новый терминал» вызывается его команда `terminal.toggle`, чтобы повторные клики не плодили терминалы. Терминал при этом открывается в правой панели, как в Claude Code.
   - Активна иконка плагина, чья вкладка активна в правой панели (ключи вкладок начинаются с id плагина); клик по активной сворачивает панель.
   - Порядок задан списком id плагинов в `native-rail.tsx`; лаунчеры других плагинов идут после.
   - «Сессия» — вкладка плагина `details` («Детали сеанса»): плагин регистрирует для неё пункт меню «+» и вкладку правой панели, во вкладке панель растягивается на всю ширину.
   - Ряд лежит поверх правого конца крайней правой панели (диалога или правой панели), а её шапка расширяет отступ `--session-header-inset-end` на ширину ряда. Кнопка «Переключить обзор» в шапке в Native скрыта: ряд её заменяет.
   - Отвергнуто: фиксированный список плагинов в коде. Он дублировал бы правила доступности, которые плагины уже знают.

5. **Меню «Вид»** переключает три существующих состояния: `appearance.sidebarOpen`, `regions.sideOpened` и `regions.bottomOpened`. Новых настроек нет. Пункт нижней панели показывается, только когда в ней есть вкладки: без вкладок панели нет на экране, хотя `bottomOpened` по умолчанию истинно.

6. **Код Native — в собственном файле `packages/app/src/session/native-rail.tsx`.** В апстримные файлы добавлены только точки ветвления по `tabLayout` с комментариями `blackbird:`, чтобы `script/blackbird-sync` давал минимум конфликтов.

## Risks / Trade-offs

- [Эталон устаревает: Claude Code меняется] → таблица сверяется со скриншотами перед реализацией (задача 1.1), дата сверки записывается в таблицу.
- [Проверки `=== "vertical"` разбросаны по апстримным файлам; новые проверки в upstream не увидят `native`] → одна функция «боковая раскладка» и тест на неё; после каждого `script/blackbird-sync` выполняется `git grep 'tabLayout() === "vertical"'`.
- [Принудительная группировка `projects` удивит того, кто в `vertical` выбрал `list`] → его настройка не меняется и возвращается при переключении раскладки; это проверяется в сценарии спеки.
- [Полоса иконок съедает ширину диалога] → ширина полосы фиксирована и узкая (как у иконок титульной панели); на мобильной ширине (< 768px) Native ведёт себя как сейчас `vertical`, то есть полоса скрыта.

## Migration Plan

Миграция не нужна: новое значение появляется только после явного выбора пользователя. Откат — выбрать другую раскладку. Если сборка без `native` прочтёт сохранённое `native`, `withFallback` вернёт `horizontal`.
