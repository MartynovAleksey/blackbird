## Context

Обе линии доставляют сообщения пользователя в работающую сессию только на границе шага (шаг — один вызов модели вместе с выполнением его инструментов):

- 1.x: `SessionPrompt.prompt` пишет сообщение в историю, `loop` присоединяется к уже работающему циклу (`SessionRunState.ensureRunning`), а цикл перечитывает историю в начале каждого шага (`packages/opencode/src/session/prompt.ts`, `runLoop`).
- 2.x: промпт попадает в `session_inbox` и по умолчанию доставляется как steer на ближайшей безопасной границе шага (`packages/core/src/session`).

Инструмент субагента в переднем плане держит шаг родителя, пока субагент не закончит (1.x `tool/task.ts` — `Effect.acquireUseRelease` вокруг `runTask`; 2.x `tool/plugin/subagent.ts` — `jobs.block`). Поэтому сообщения родителю ждут конца субагента.

Перевод блокирующих субагентов в фон уже существует:
- 2.x: `Session.background` → `Job.backgroundAll`, команда `session.background` (ctrl+b) и подсказка `BackgroundToolHint` для работающих `shell`/`subagent`; работает без флагов, после перевода в сессию добавляется синтетическое пояснение для модели.
- 1.x: `BackgroundJob.promote`, эндпоинт `experimental.session.background` и команда `session.background` (ctrl+b), но эндпоинт и подсказка включены только при `OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS`. После перевода `onPromote` подписывается на завершение и добавляет результат в родителя синтетическим промптом.

Сервер обеих линий принимает промпт в сессию работающего субагента и доставляет его на границе шага субагента. Мешает только TUI: в сессии субагента поля ввода нет (1.x — `visible` в `routes/session/index.tsx` скрывает его при `parentID`; 2.x — вместо поля открыт композер с вкладкой субагентов).

## Goals / Non-Goals

**Goals:**
- Сообщение основной сессии доходит до агента сразу, а не после субагента, без прерывания субагента.
- Пользователь корректирует работающего субагента из его сессии.
- Одинаковое поведение в 1.x и 2.x.

**Non-Goals:**
- Доставка внутрь шага, который ждёт другой долгий инструмент (например, многочасовой `bash` в самом субагенте): корректировка ждёт конца этого инструмента, как и сейчас.
- Пересылка корректировки из основной сессии в субагента: корректировка пишется в сессии субагента.
- Изменения серверного API промпта и сгенерированного SDK.

## Decisions

**«Отправить сейчас» = очередь + перевод в фон, а не новая клавиша.** Enter по-прежнему ставит сообщение в очередь. Если сессия ждёт субагента, рядом с сообщением в очереди и в подсказке инструмента показывается действие `session.background` (ctrl+b) как «отправить сейчас»: субагенты уходят в фон, шаг родителя завершается, и сообщение доставляется на этой границе.
Альтернатива — отдельная привязка для отправки сразу, например ctrl+enter. Отказ: терминалы без протокола kitty (в том числе JediTerm в плагине IDE) не отличают ctrl+enter от Enter, а новая привязка дублировала бы ctrl+b.

**1.x: перевод в фон по запросу пользователя без флага.** В `experimental.session.background` убирается проверка `experimentalBackgroundSubagents`, в TUI подсказка и команда `session.background` не зависят от `capabilities.experimentalBackgroundSubagents`. Параметр `background` для модели в `TaskTool` остаётся под флагом: решение о фоне принимает пользователь, а не модель.
Альтернатива — включить флаг по умолчанию в blackbird. Отказ: модель стала бы сама запускать фоновые субагенты, а это отдельное изменение поведения.

**Корректировка субагента — обычный промпт в его сессию.** В сессии субагента TUI показывает поле ввода, пока сессия занята (статус busy). Отправка — тот же промпт, что в основной сессии, но с агентом и моделью субагента: в 1.x `runLoop` берёт агента и модель из последнего сообщения пользователя, а поле ввода TUI по умолчанию подставляет агента, выбранного в основной сессии. Без этого корректировка переключила бы субагента на агента родителя.
2.x: поле ввода показывается вместе с вкладкой субагентов, промпт отправляется с доставкой steer.
Альтернатива — отдельный серверный метод «steer subagent». Отказ: существующий промпт уже делает нужное.

**Когда субагент не работает, поле недоступно.** Промпт в простаивающую сессию субагента запустил бы новый цикл, ответ которого не дошёл бы до родителя. Поле показывает подсказку: продолжить субагента можно из основной сессии (модель передаёт `task_id` в 1.x или `sessionID` в 2.x).

## Risks / Trade-offs

- [Основной агент после «отправить сейчас» берётся за работу, пересекающуюся с фоновым субагентом] → 2.x уже добавляет синтетическое пояснение «работа в фоне не завершена»; в 1.x модель видит результат инструмента «Background task started». Отдельной защиты от конфликтов в файлах нет, как и для фоновых субагентов сейчас.
- [Корректировка ждёт долгий инструмент внутри шага субагента] → это вне цели; при необходимости пользователь прерывает субагента.
- [Правки апстримных файлов TUI конфликтуют при синхронизации] → правки точечные, с комментариями `blackbird:`.
- [В 1.x после снятия флага пользователи увидят подсказку ctrl+b, которой раньше не было] → это и есть цель; поведение без нажатия не меняется.

## Migration Plan

Флагов и миграций данных нет. Изменения выпускаются обычными релизами обеих линий; откат — откат коммитов.
