# upstream-sync Specification

## Purpose
Две линии форка обновляются из релизных тегов апстрима opencode одной командой при минимальной поверхности изменений.

## Requirements

### Requirement: Две линии форка
Репозиторий SHALL содержать две долгоживущие ветки кода: `blackbird/v1`, основанную на релизном теге `v1.*`, и `blackbird/v2`, основанную на релизном теге `v2.*` репозитория `github.com/anomalyco/opencode`. Активные ветки апстрима (`dev`, `v1`) MUST NOT использоваться как основа. Апстрим SHALL быть подключён как git remote `upstream`.

#### Scenario: Ветки и remote существуют
- **WHEN** разработчик выполняет `git branch -a` и `git remote -v` в репозитории blackbird
- **THEN** видны ветки `blackbird/v1`, `blackbird/v2` и remote `upstream`, указывающий на `github.com/anomalyco/opencode`

#### Scenario: Происхождение веток
- **WHEN** выполняется `git describe --tags --abbrev=0 blackbird/v2`
- **THEN** возвращается релизный тег апстрима `v2.*`, на котором основана линия (сейчас `v2.2.5`)

### Requirement: Обновление из апстрима одной командой
Для каждой линии SHALL существовать документированная процедура обновления (`script/blackbird-sync` в каждой ветке), которая принимает релизный тег, проверяет, что он относится к линии ветки, делает `git fetch` этого тега из `upstream` и `git merge` тега в ветку blackbird, после чего прогоняет проверку ребрендинга.

#### Scenario: Чистое обновление
- **WHEN** апстрим добавил коммиты, не затрагивающие изменённые blackbird строки, и в `blackbird/v2` запущен `script/blackbird-sync v2.2.6`
- **THEN** merge проходит без конфликтов и проверка ребрендинга зелёная

#### Scenario: Тег другой линии
- **WHEN** в `blackbird/v2` запущен `script/blackbird-sync v1.19.6`
- **THEN** скрипт отказывается работать и ничего не мержит

#### Scenario: Конфликт
- **WHEN** апстрим изменил строку, которую правит blackbird
- **THEN** скрипт останавливается на конфликте git, ничего не коммитит автоматически и сообщает, какие файлы конфликтуют

### Requirement: Минимальная поверхность изменений
Изменения blackbird относительно апстрима SHALL ограничиваться правкой строк в существующих файлах и добавлением новых файлов; файлы апстрима MUST NOT удаляться или переименовываться.

#### Scenario: Diff не содержит удалений и переименований файлов
- **WHEN** выполняется `git diff --name-status v2.2.5...blackbird/v2`
- **THEN** в выводе нет записей со статусом `D` или `R`
